# Test vectors — suite `opi-0 / 2026-08-29`

The vectors are the executable half of the specification (§16.5). Each
directory was written with its chapter and keeps that chapter's shape; the
shapes differ, and this file documents each honestly rather than forcing one
format. Run them all against a validator with:

```
python tools/conformance/run.py --validator "your-validator --json {file}" --report report.json
python tools/conformance/run.py --self      # the reference validator, must be all-pass
```

Two kinds of vector exist:

- **Complete-file vectors** describe a whole `.opi` (either a file on disk
  or a manifest the runner materialises into a Core ZIP). Expectation is
  `valid` or `must-fail <check name>`. These test the **Validator** class.
- **Unit vectors** exercise one function — a rate label, a drop-frame
  conversion, a `run_id` derivation, an interop string. A Validator's
  internals should reproduce them; the runner reports them as `unit-only`
  because they cannot be handed to a validator as a file.

| Directory | Chapter | Kind | Files |
|---|---|---|---|
| `manifest/` | §5, §6, §8 | complete files (manifests), plus schema-only rules as unit | 15 |
| `time/` | §6A | unit, plus `consistency.json` as complete files | 5 |
| `runs/` | §7 | complete files (manifests), plus `valid-run-id.json` and `valid-rerun-replace-in-place.json` as unit | 11 |

## `manifest/`

The envelope key by key, regenerated by `make_vectors.py` (`--check`
verifies the checked-in JSON). Each file is `{"title", "spec", "manifest",
"expect"}` with

```
expect = {"schema":    "valid" | "invalid" | null,   # schema/opi-0.schema.json
          "validator": "valid" | "invalid" | null,   # the reference validator
          "check":     <the validator row a must-fail vector is rejected by> | null}
```

`validator: null` marks a rule the **schema** enforces and no validator row
does yet (§5's table convention) — `role` outside the enumeration, a
non-RFC-3339 `generated_at`, a `labels[]` entry missing `created_by`. Those
cannot be handed to a validator as a file, so the runner reports them
`unit-only`; `tests/test_manifest.py` asserts the schema verdict instead.
`invalid-oversize.json` carries no manifest at all — a 16 MiB document is
described, not shipped — and names the check (`manifest size`) a validator
must report without parsing.

Every other file is a **complete file**: the runner writes `manifest` as a
Core ZIP and expects exit 0 (`valid`) or exit 1 for the named `check`.

## `time/`

Five JSON documents, each `{"description": str, "cases": [...], ...}`.

- `rates.json` — `cases[]`: `{rate{num,den}, drop_frame, label, nominal,
  dropped_per_minute, has_timecode}`; `labels[]`: label ↔ rate parsing,
  including labels that MUST be rejected. **Unit.**
- `timecode.json` — `cases[]`: `{rate, drop_frame, label, frames,
  seconds{num,den}}` — frames ↔ timecode ↔ exact seconds, NDF and DF, across
  the drop points; `sequence_29_97_DF_across_first_minute`: consecutive
  frames around `00:00:59;29 → 00:01:00;02`; `labels[]`: edge cases. **Unit.**
- `spans.json` — `cases[]`: `{rate, t_start_s, t_end_s, frame_in, frame_out,
  t_start_s_exact, t_end_s_exact}` — the floor-in / ceil-out rule. **Unit.**
- `consistency.json` — `cases[]`: `{rate, drop_frame, start, span, valid,
  note, errors?}`. Each case is materialised by the runner into a manifest
  with that `timecode` and one `shots` entry carrying `span`; `valid: false`
  cases MUST fail a `time: span …` check. **Complete file.**
- `interop.json` — `cases[]`: `{rate, drop_frame, start, frames, fcpxml_time,
  fcpxml_frameDuration, otio{…}, edl_fcm, edl_source_tc, xmeml{…}}` — the
  §6A.6 round-trip strings. **Unit.**

## `runs/`

- `valid-run-id.json` — `{"description", "cases": [{producer, model_version,
  sha256, payload, run_id}]}`: the §7.1 derivation, `payload` being the exact
  JCS bytes hashed. **Unit.**
- `valid-*.json`, `invalid-*.json` — `{"manifest":
  {...}, "expect": {...}}`. `expect.all_ok: true` → the file is valid;
  `expect.failing: [check names]` → must fail, and those `runs:` checks are
  the expected reasons; `expect.current: [run_ids]` → what §7.3 selects as
  current (a Reader assertion, R7); `expect.lineage_of_new` → §7.3 lineage.
  The runner writes each `manifest` as a Core ZIP. **Complete file.**
- `valid-rerun-replace-in-place.json` — `{"secret_key_hex", "before", "after",
  "expect": {same_run_id, before_status, after_status,
  before_signature_invalid_on_after}}`: a signed run re-run at the same
  identity. The key is RFC 8032 test key 1, so the recorded signatures are
  reproducible. **Unit** (the runner also materialises `before` and `after`
  as valid files).

## `members/`

Binary vectors, regenerated deterministically by `make_vectors.py`
(`--check` verifies the checked-in bytes). `expected.json` has two parts:

- `valid.file` (`valid-full.opi`) with its `sha256` and the exact
  `data_offsets` of each aligned member — a Reader computing offsets from
  the local header MUST get these numbers.
- `cases[<file>]` — `{must_fail: <check name>, why: <rule>}` for each
  `case-*.opi`.

Every `.opi` here is a **complete file**.

## `facets/`

`valid-<facet>.json` and `invalid-*.json`, each `{"facet": name, "entry":
entry | [entries], "expect_failure_in"?: <check-name fragment>}`. The
`stable` facets' valid entries were taken from a real producer run. These
are unit vectors for `facets.checks()`; the runner also materialises each
into a complete file by wrapping the entries in one run
(`conformance:vectors`, derived `run_id`) over a 23.976 fps medium — adding
`"confidence": null` to entries that omit the key, because §7.5 requires the
key on every entry in a complete file while the facet vectors describe the
facet alone. `expect_failure_in` is matched as a substring of the failing
check's name. **Complete file (wrapped).**

## Adding a vector

Put it in the directory of the chapter it exercises, follow that
directory's shape, name it `valid-*`, `invalid-*`, or `case-*` (`case-*`
is a valid container exercising one edge), and
make sure `python tools/conformance/run.py --self` still passes. A vector
that the reference validator does not agree with is a bug in one of them;
fix the bug, do not delete the vector.
