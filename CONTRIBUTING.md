# Contributing to Open Picture Intelligence

`.opi` is a format first and a codebase second. Most contributions fall into
one of three kinds, and each has a different bar.

## 1. Changes to the specification (`spec/`, `schema/`)

The normative text lives in `spec/`, one chapter per file; `SPEC.md` is
generated by `python tools/build_spec.py` and drift-tested. The spec is the product. A change to it is a change to every file anyone has
ever written, so:

- Open an issue first describing the problem the change solves and which
  existing files it would affect. "It would be cleaner" is not a problem.
- Additive changes (new optional keys, new facet vocabulary) are welcome while
  the major version is `0`. Readers ignore unknown keys; that is what makes
  additions safe.
- Anything that changes the meaning of an existing key, the signature payload,
  the container rules or the detection algorithm is a major-version change
  and needs the steward's sign-off (see `docs/contribute/governance.md`).
- Every spec change lands with: the SPEC text, the schema, a test in
  `tests/`, a CHANGELOG line, and — if it touches bytes — a regenerated
  `tools/opi_verify.py` (`python tools/build_bundle.py`).

## 2. Changes to the reference implementation (`openpicture/`)

- **Standard library only.** No third-party imports in `openpicture/`. The
  whole point is that the validator can be copied anywhere Python runs. If
  `cryptography` is present it is used as a fast path; it is never required.
- Every behaviour has a test. Run `.venv/bin/python -m pytest -q` — all green
  before a PR.
- If you change `jcs.py`, `ed25519.py`, `container.py`, `sign.py` or
  `validate.py`, regenerate the single-file validator and commit it; the
  drift test fails otherwise.
- Keep the examples valid: `openpicture validate examples/*.opi` must say
  `valid-signed`. If you must regenerate them, re-sign with
  `examples/example-producer.key` and update `examples/README.md`.

## 3. Documentation (`docs/`, `README.md`)

Docs build with MkDocs (`pip install -r docs-requirements.txt && mkdocs
serve`). `mkdocs build --strict` must pass: no broken links, no warnings.
Prose is neutral and precise — this is a standards project, not a pitch.

## Versioning

Package versions stay `0.0.x` during the public, pre-freeze alpha. The patch number bumps on every merge to `main`. Nobody bumps
the minor or major without the steward's explicit approval.
