# The human layer

## `editorial_annotations` belongs to whoever holds the file

The third top-level block is for people. Ratings, notes, scene and take
numbers, a MAM's tags, the labels a client applies in their own vocabulary.
It is a JSON object; the format constrains it only to *be* an object.

```json
"editorial_annotations": {
  "labels": [{"name": "select", "value": "hero", "created_by": "D",
              "span": {"frame_in": 0, "frame_out": 48}}],
  "rating": 5,
  "notes": "director's pick"
}
```

## It is never signed

The machine layer is signed per run. The human layer is deliberately
outside every signature. An editor changing a tag in Resolve, an assistant
adding a scene number, a MAM writing back a category — none of that
"corrupts" the file. A reader that treats a changed human layer as
tampering is non-conformant.

The trade is attribution: because it is unsigned, nothing in the human
layer can be proven to come from anyone. Systems that need *attributable*
human annotations record them as a signed run by a human-operated producer
key, not here.

## It survives a rewrite

When a producer regenerates a sidecar — a new model pass, a re-index — it
reads the existing file's `editorial_annotations` first and carries forward
every key it does not own. The reference producer owns `labels` (its store
is the authority on those); `rating`, `notes`, and anything else are the
holder's and are preserved verbatim.

Without this rule every regeneration would silently destroy the editor's
work, which is the most expensive failure a sidecar can have. It is a MUST
for writers.

```bash
openpicture annotate clip.mov.opi --set rating=5 --set notes="director's pick" --label scene=42B
```

`annotate` edits only this block. It snapshots the machine layer before and
after, re-verifies every signature, and refuses the edit if anything else
would change.

## Read-back is the producer's contract with its own store

Whether a producer reads the human layer back into its own database is
outside the file format. If it does, the specification requires it to
record provenance (the reference producer imports with
`created_by = "opi:<signer or filename>"`), never delete or overwrite an
existing value (conflicts are kept side by side, timestamped), and never
import anything from the machine layer — that is regenerated by re-running
producers, not copied.

```bash
latent import opi clip.mov.opi
# imported 1 file(s): 3 label(s) added, 0 already present, 0 conflict(s) kept side by side
```

*Any producer's importer works the same way — Latent is simply the only one
that exists today.*

*Normative text: specification §8.*
